## 2. 实际浏览器链路

1. 登录 AutoSpec，创建项目 `P4-E 浏览器演示`（隔离数据库项目 ID `38`）。
2. 输入个人任务清单需求，包含任务创建/完成/筛选、登录保护、状态持久化、空列表提示、成功反馈和未授权请求 `401` 验收条件。
3. 从已发布 `pm-schema-repair-v12 · #1` 启动正式 `POST /api/workflow-runs` 对应的工作流；没有调用同步 `/generate*` 接口。
4. 运行 `#43` 选择均衡配置，Product Manager 审批后在 `frontend_engineer` 预授权阶段以 `BUDGET_PREAUTH_FAILED` 终止；该负例证明预算边界在浏览器链路中可见。
5. 运行 `#44` 选择深度配置，审批理由为 fixture 演示用途；Product Manager 审批后，六个正式节点均到达终态：Product Manager、Architect、Backend Engineer、Frontend Engineer、Reviewer 成功，Evaluator 以 `QUALITY_GATE_BLOCKED` 失败。
6. 在 Trace 页面实际观察到：Bundle/Contract hash、排队 `8,000 ms`、执行 `152 ms`、模型调用 `6`、重试/恢复 `0/0`、两个 `spec.verify` 工具调用，以及 Backend Agent Loop 的 `PLAN_ACCEPTED`、`CANDIDATE_READY`、`VALIDATION_PASSED`、`SPEC_VERIFY_PASSED`、`COMPLETED` 步骤。
7. Evaluator 的阻断理由为：`REQ-SEARCH` 缺少 acceptance criteria 的追踪证据，以及 `/api/products` 项目级 API 缺少认证或角色覆盖。该结果是预期的 fixture 质量门禁负例，不是交付通过。
